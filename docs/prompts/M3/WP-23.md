TESTS (injected clock, no real sleeps):
- Each threshold fires once: ten evaluator runs across 8 days → exactly 7 d, 3 d, 1 d, due day, overdue, one each;
  a second run in the same minute inserts nothing. Deadline moved later → the thresholds re-arm on the new
  `dueAt`; moved earlier past two thresholds → one notification. A DATE deadline's due day is its Kolkata day.
- **Sleep**: clock jumps from 4 d before to 20 h before → catch-up fires only 1 d, never 3 d, then or later.
- Snooze: hidden until `until`; at `until + 1 tick` it is back, unread, and published; dismiss never returns.
- Recipients: co-mentor whose period ended gets nothing; the user who overrode a deadline is not told; a
  saved-only event never produces OVERDUE; admin notices go to admins only; preference off → no row; threshold
  override `[14,2]` honoured; every `NotificationType` has a registry default (fails if one is added bare).
- Stream: a recipient's stream receives the id, another user's does not; degraded client polls.
- Rust (R19): badge precedence, badge digits and "9+", route validation, activation handler.
