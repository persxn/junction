| R112 A saved search starts from a baseline | "New" means an event id this search has **never** matched. Matches live in `saved_search_matches` (saved_search_id, event_id, first_matched_at; PK both; cascade on delete) — a set, not a JSON blob; `last_result_hash` (SHA-256 of the sorted ids) short-cuts an unchanged run. Creating a search, or changing its query, records the current matches **silently**: nobody is told "57 new matches" for a search they just made. An event that leaves and comes back is not new. One run → at most **one** NEW_MATCH per search summarizing N events, keyed `NEW_MATCH:saved_search:<id>:<hash of the new ids>`. With `notify_on_new` off the set still advances. | §6.2, §12, R108 |
| R113 Interests are tags; a category interest is a tag | "My interests" writes only `user_interest_tags`. A category interest is an INTEREST-kind tag whose normalized name is the category's slug — exactly WP-15b's matching rule — created on first use, so ranking needs no new join. Interests are personal and not audited; they change ranking only for their owner. The team-skills boost of §8.4 stays out of the MVP Recommended feed. | §8.4, D-18, WP-15b |

BUILD:
1. **Contracts**: `SavedSearch` {id, name, query: EventQuery, notifyOnNew, lastEvaluatedAt?, version}, create/patch
   DTOs, `MyInterests` {categoryIds, tagIds}; `SAVED_SEARCH_` ErrorCodes (R12). A stored query is parsed with
   `EventQuery` on read; one that no longer parses is returned flagged `invalidQuery` and never evaluated.
2. **Migration** (`db:generate`, next free number, never `push`; `pnpm typecheck` first): `saved_searches` per
   §6.2 + `version`, `updated_at`; `saved_search_matches` (R112); UQ(user_id, name).
3. **Pure domain** (`src/domain/saved-searches/`): `diffMatches(previousIds, currentIds)` → new ids,
   `resultHash(ids)`, `newMatchNotification(search, newEvents)` → title "3 new events match “AI hackathons near
   campus”", body with up to 3 titles and "and N more", route = Discover with the search applied.
4. **Evaluation**: the search module gains an **ids-only** path for an `EventQuery` (same builder as `POST
   /search/events` — no second filter implementation), forcing `excludeHidden` for the owner and ignoring
   sort/cursor/limit. Job `saved-search-evaluator` (R22): GENERAL, hourly, not network-gated, **and** triggered
   on every `source.run.finished` with outcome SUCCESS or PARTIAL (R86 — subscribe in-process to the hub or the
   orchestrator's finish hook, then `scheduler.trigger()`; single-flight coalesces a burst of runs into one).
   Emit through WP-23's `notifications.emit` (it honours preferences); set `last_evaluated_at` and the hash.
5. **Routes** (owner only; another user's id → 404): `GET/POST /saved-searches`, `PATCH/DELETE
   /saved-searches/:id` (`version` → 409), `GET/PUT /me/interests`, `POST/DELETE /me/interests/categories/:id`.
6. **Discover**: "Save this search" beside the chips → dialog (name, "Tell me about new matches" on by default) —
   the query comes from `query.ts`, the one chips ↔ `EventQuery` place. A **Saved searches** menu by the tabs:
   apply (writes the query back into the chips and router state — a round trip test), "Update with current
   filters" (re-baselines, R112), rename, toggle alerts, delete with Undo. A NEW_MATCH notification opens Discover
   with the search applied.
7. **My interests** (user menu → dialog, and the Dashboard's Recommended empty state): active categories as a
   checkbox list; tags as a combobox over existing tags (TECHNOLOGY · THEME · SKILL), with "Add “…” as an
   interest" creating an INTEREST tag. In the event drawer each category chip gets **"More like this"** — adds the
   category interest with an Undo toast. Any change invalidates every RELEVANCE query key.
8. **Recommended** (Discover tab and Dashboard panel): RELEVANCE, no text, `excludeHidden`, for the current user.
   **Every card shows its reasons inline** — the first two as text on the card, all of them under "Why
   relevant?" — reusing WP-15b's reason objects; add the interest wording only where a code lacks it
   ("AI/ML matches your interests", "Tagged Rust — one of your interests"). No interests yet → a banner "Pick
   your interests to sharpen these" + button, and the list still shows (deadline and trust reasons). D-18: rules
   only, no AI.
