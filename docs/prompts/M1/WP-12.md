BUILD:
1. **Source row** (update the WP-09a seed, upsert by key, keep `version`): adapter `DEVFOLIO`, kind `HTML`,
   `cadence_minutes` 15, `manual_min_interval_minutes` 5, `min_delay_ms` 3000 (the effective delay is still
   max(3 s, this, robots `Crawl-delay`) — A9), `max_requests_per_run` = 1 listing + ≤ 10 details,
   `trust_rank` = registration-platform tier (above CTFtime and CLIST, below an organizer's own site),
   `compliance_status` APPROVED_WITH_LIMITS, notes recording that the Terms are **silent** on scraping and that
   the courtesy permission e-mail (U5) is outstanding. `config_json.hosts` = `devfolio.co` and `*.devfolio.co`;
   `allowed_paths_json` = `/hackathons` on `devfolio.co` and `/` on any `<slug>.devfolio.co`.
2. **Hard rule: `api.devfolio.co` is never called.** Put `api.devfolio.co` in a deny-host list checked *before*
   the transport in the adapter's fetch helper, throwing `SOURCE_HOST_FORBIDDEN` (R12 prefixing). Any URL
   discovered inside a payload that points at that host is ignored, never followed. This is an acceptance
   criterion — see TESTS.
3. **Per-subdomain robots.** Every `<slug>.devfolio.co` is its own host: robots is fetched and cached per host
   for 24 h by WP-09a's client. The adapter must not assume the apex's robots covers a subdomain. A subdomain
   whose robots disallows `/` → that detail is **skipped without a request**, the listing-level candidate is kept
   with a parse warning, and the run outcome is PARTIAL.
4. **Extraction** `src/adapters/devfolio/extract.ts` — pure over an HTML string. Read the
   `<script id="__NEXT_DATA__" type="application/json">` payload with cheerio (never a regex over the document),
   `JSON.parse`, then navigate `props.pageProps`. Listing buckets: `open_hackathons`, `upcoming_hackathons`,
   `past_hackathons`, `featured_hackathons` (walk open + upcoming; `past_` only to close out records already
   known — §7.6). Detail: the `hackathon` object plus `aggregatePrizeValue`/`aggregatePrizeCurrency`/
   `prizeDetails[]`. Validate each payload with a zod schema that **requires** the core keys and tolerates
   unknown ones.
5. **A format change is loud, never silent.** A missing script tag, unparseable JSON, or a payload that fails the
   zod shape → `AppError` kind `SCHEMA_CHANGED`; the run ends `FAILED` with `error_kind = SCHEMA_CHANGED`,
   `consecutive_failures` increments (so the source backs off, §7.2), **zero events are written**, and the raw
   response is kept as a snapshot (§7.8) so the fixture can be regenerated. Distinguish this from the legitimate
   case where every bucket key is present and empty: that is `SUCCESS` with `items_seen = 0`. Both are tests.
6. **PII is dropped at the adapter boundary (D-29), by construction not by filtering.** `src/adapters/devfolio/
   map.ts` builds the candidate by copying an **explicit allowlist** of fields; anything unnamed never leaves the
   adapter. Named drops, asserted by test: `participants_details[]`, `judges[]`, `mentors`, `settings.contact_email`
   and every social handle except `settings.site`. Then run WP-08a's redactor over `desc`, `tagline` and
   `faqs[].answer` so e-mails and phone numbers inside prose become "[contact details on the source page]".
7. **Field mapping** (feasibility §3.5 is the reference): `name`→title · `starts_at`/`ends_at`→dates ·
   `timezone`→IANA (**`Asia/Calcutta` must alias to `Asia/Kolkata`**) · `settings.reg_starts_at`/`reg_ends_at`→
   registration window · `is_online` + `settings.is_hybrid`→ONLINE/HYBRID/OFFLINE · `city`/`country`/`location`→
   geography via WP-08b · `team_min`/`team_max` (detail only) · `settings.paid === false`→`fee_known` with 0,
   `true`→unknown with the original text · `type`→HACKATHON · `settings.site`→official URL,
   `https://<slug>.devfolio.co`→registration URL · `desc`→sanitized Markdown · `themes[].theme.name`→tags.
   **`organizer_name` is not a field on Devfolio** — infer from `location`/site host at low confidence, or leave
   unknown. Never invent one. `external_key` = `devfolio:<uuid>`.
8. **Listing→detail discipline:** one listing request per run; `detail()` only when a listing item's
   `content_hash` changed; conditional GET (ETag/Last-Modified); the per-run detail cap leaves the remainder for
   the next run; ≤ 1 concurrent request per host. A full walk of open + upcoming inside the caps sets
   `listing_complete = true` (A8).
