Two features in one slice: a professor types an event in by hand, or pastes a link and reviews what we could
read from it. This is the first M1 WP with a real form; the Discover UI proper is WP-16a.

BUILD:
1. **Contracts** (`packages/contracts/src/events-import.ts`): `ManualEventInput` (title required, every other
   field optional, same vocabulary as `EventCandidate`), `UrlImportRequest { url }`,
   `UrlImportResult { disposition: 'ADAPTER' | 'MANUAL_ONLY' | 'GENERIC', sourceKey?, candidate?, reason?,
   fieldsFound[], warnings[] }`. Error codes (R12, `IMPORT_` domain): `IMPORT_URL_INVALID`,
   `IMPORT_DOMAIN_MANUAL_ONLY`, `IMPORT_ROBOTS_DISALLOWED`, `IMPORT_EXTRACTION_FAILED`,
   `IMPORT_UNSUPPORTED_CONTENT`, `IMPORT_RATE_LIMITED`. Schema tests per type.
2. **Dispatch is a pure function** — `src/domain/import/route.ts`, `resolveImportRoute(url, sourceRows)`:
   normalize first (https only — http and every other scheme is `IMPORT_URL_INVALID`; lowercase host; drop
   `www.`; strip tracking parameters; reject IP literals and `file:`/`data:`), then match the host and its
   registrable parent against each source's `config_json.hosts` (so `<slug>.devfolio.co` matches
   `*.devfolio.co`). Then:
   - APPROVED / APPROVED_WITH_LIMITS **and** the adapter implements `detail()` → `ADAPTER`
   - MANUAL_IMPORT_ONLY / BLOCKED → `MANUAL_ONLY` — **no request of any kind, robots.txt included**
   - no match → `GENERIC`
   The table is derived from the live `sources` rows, never a second hard-coded list, so WP-13's verdict for
   Unstop and D-26's verdict for Devpost apply automatically.
3. **ADAPTER path:** build a synthetic `ListingItem` from the URL and run that adapter's `detail()` +
   `normalize()` through the same `PoliteHttpClient` and compliance gate as a scheduled run (robots, effective
   delay, request caps, snapshots). Write a `source_records` row owned by that source, so provenance, trust rank
   and later scrapes merge normally through WP-10 (§7.5).
4. **MANUAL_ONLY path:** return the disposition, the source's display name and its `compliance_notes` as
   `reason`. The UI opens the manual form with `official_url` pre-filled and a banner in the source's words —
   e.g. "Devpost doesn't allow automated reading, so type the details in. The link is saved with the event."
   Zero network calls; nothing is written until the professor saves.
5. **GENERIC path:** one request, under the seeded `url-import` source row (adapter `URL_IMPORT`,
   `is_enabled = false`, never scheduled, `min_delay_ms` 3000, `max_requests_per_run` 1). Rules: robots checked
   for that host first (disallowed → `IMPORT_ROBOTS_DISALLOWED`, no page request), HTML only (anything else →
   `IMPORT_UNSUPPORTED_CONTENT`), 5 MB cap, **no link following, no second page, ever**. Extraction
   (`src/domain/import/extract.ts`, pure over an HTML string) in order: schema.org `Event` JSON-LD → Open Graph /
   Twitter cards → heuristics (`<title>`, first `<h1>`, `<time datetime>`, WP-08a's date parser over labelled
   prose, the most registration-like outbound link). Every field carries a confidence and its original text;
   nothing is guessed; WP-08a's PII redactor runs over all extracted prose (D-29). Nothing found at all →
   `IMPORT_EXTRACTION_FAILED` and the manual form opens anyway with the URL attached.
6. **Provenance and overrides.** Manually created events belong to the seeded `manual` source (adapter `MANUAL`,
   `is_enabled = false`, never scheduled); imported ones to the adapter's source, or `url-import` for the
   generic path. Every value the professor typed or edited in the review step is written as an `event_overrides`
   row (`reason` = "manual entry" or "URL import review", `set_by` = the user) so a later scrape never
   overwrites it (§7.5); deadlines get `origin = MANUAL`. Every write goes through `withAudit` in the same
   transaction (R35): `event.created.manual`, `event.imported.url`.
7. **Routes** (`src/modules/events/import/`): `POST /api/v1/events/import/preview` → `UrlImportResult`, **never
   writes anything**, limited to 10 per minute per user so it stays user-initiated; `POST /api/v1/events/import/commit`
   → runs WP-10's matcher (an identical normalized URL merges into the existing event and adds a source record
   instead of creating a duplicate); `POST /api/v1/events` for the manual create. Permissions from the §10.2
   matrix via `assertCan` — if the matrix has no event-create action, use the nearest one and say so in the
   report.
8. **UI** `apps/desktop/src/features/events/create/`, on WP-06's shell, tokens and states. One form, two entry
   points: **Add event** (blank) and **Import from link** (paste URL → preview → the same form, pre-filled, each
   pre-filled field carrying a small source chip and a "found on the page" hint, low-confidence fields visibly
   marked). Rules: every field has a label, an error message and a keyboard path; Save stays disabled until
   there is a title plus either a date or a link; the preview lists what was found **and what was not**; there is
   a distinct state per error code (R5 problem details rendered, never a raw stack); the MANUAL_ONLY banner is
   its own state, not an error toast; empty and error states come from WP-06; **axe clean** on every step.
9. **The five sample imports** (the §19 acceptance criterion) — fixtures in
   `apps/backend/test/fixtures/url-import/`, each driven end to end with a transport spy:
   1. a Devfolio subdomain hackathon page → `ADAPTER`, candidate from WP-12's adapter;
   2. a CTFtime event URL → `ADAPTER`, detail through the documented API;
   3. **a Devpost hackathon URL → `MANUAL_ONLY` with zero transport calls;**
   4. a campus page carrying `Event` JSON-LD → `GENERIC`, high-confidence fields;
   5. a campus page with only Open Graph plus prose dates → `GENERIC`, low-confidence fields and warnings.
   Goldens via `expectGolden`; `UPDATE_GOLDEN=1` to refresh.

SESSION ACCESS (owner ruling R74 / D-34 — **decided, do not re-open**; the owner accepts the account risk):
10. **What it is.** For Devfolio and Unstop, the professor may give the app their **own** signed-in session so
    the adapters read pages as that professor. Read-only: GET requests only, to that source's allowed hosts,
    through the same `PoliteHttpClient`, gate, robots, effective delay, caps and backoff. Never create an
    account, never use anyone else's session, never solve or bypass a CAPTCHA, never submit, register or change
    anything on the platform. `api.devfolio.co` stays forbidden with or without a session.
11. **Storage.** Reuse WP-11's credential mechanism: `config_json.auth` names the header (`Cookie`) and two
    **secret** settings per source (`sources.<key>.sessionCookie`, `sources.<key>.sessionCapturedAt`). The value
    is never logged, never exported (`exportableSettings()`), never echoed by an API, and sent **only** to the
    source's own hosts (for Devfolio: `devfolio.co` and `*.devfolio.co`; never another host, never robots.txt).
    Store only the cookies for that source's domain, not the whole browser jar.
12. **Two ways in**, both admin-only (§10.2 `source.manage`), both audited without the value:
    a. **Paste** — `PUT /api/v1/admin/sources/:key/session` with the cookie string copied from the professor's
       browser (dev tools → Application → Cookies, or a "copy as cURL" header); `GET …/session` returns
       `{ isSet, capturedAt, lastVerifiedAt, state }` and nothing else; `DELETE …/session` signs the app out.
    b. **In-app login window** — the Tauri shell opens a dedicated `WebviewWindow` on the source's own login page
       with a **separate, persistent data directory** (never the main UI's webview), lets the professor sign in
       there (2FA and CAPTCHAs are the professor's to solve, by hand), then reads **only that domain's cookies**
       via Tauri's cookie API, hands them to the backend over the typed IPC (R24), and closes. The window
       loads nothing but the source's hosts; navigation elsewhere is blocked. UI entry: Admin → Sources → a
       source row → "Sign in" / "Paste session" / "Sign out", with the state shown.
13. **Session state is a source state.** A 401/403 or a redirect to the login page while a session is set →
    the session is marked `EXPIRED` (a source state shown in Source status: "Your Devfolio session expired —
    sign in again"), the run records `BLOCKED` with that detail, **no backoff escalation**, and subsequent runs
    fall back to the public pages until a new session is provided. No retry with another identity (R60).
14. **What a session may add.** Fields only visible when signed in may be read into the existing
    `EventCandidate` fields (eligibility, deadlines, fees, team rules, prizes). The professor's **own**
    registrations and teams on the platform may be stored as a new, clearly-owned record type if a field for
    it is needed — say so in the report and keep it to that professor's account. **Other people's participant,
    judge, mentor and contact data is still dropped at the adapter boundary (D-29)**; asserting that with a
    signed-in fixture is part of the tests. If the owner later wants more than this, it needs a new ruling.

- generic path: robots disallow → `IMPORT_ROBOTS_DISALLOWED` with no page request; a PDF → `IMPORT_UNSUPPORTED_CONTENT`;
  a 6 MB body is refused; exactly one request per import and no link following.
- extraction goldens for samples 4 and 5; the PII redactor strips an e-mail and a phone number from an imported
  description (D-29).
- overrides: a manual create writes one `event_overrides` row per supplied field, and a **subsequent scrape of
  the same event through WP-10 leaves every overridden value unchanged** while still recording the source's
  claim; `event_changes` shows the scrape's claim, not a silent overwrite.
- duplicate import: importing the same URL twice merges and produces one event with two source records.
- audit rows for create, import and override; preview writes nothing (assert row counts before/after).
- **sessions:** the cookie is sent only to the source's own hosts (a transport spy over a run with a
  Devfolio session sees the `Cookie` header on `devfolio.co`/`*.devfolio.co` pages and **never** on robots.txt,
  another host or `api.devfolio.co`); it never appears in a captured log stream, a snapshot, an audit row, an
  API response or `exportableSettings()`; a 401/redirect-to-login marks the session EXPIRED with no backoff and
  the next run uses public pages; the professor role gets 403 on every session route; a signed-in Devfolio
  fixture still yields no participant/judge/contact key or e-mail/phone pattern (D-29); the login window's
  cookie hand-off is covered by a Rust unit test on the domain filter (only the source's domains pass).
- UI: preview → pre-filled form; the MANUAL_ONLY banner with the link attached; Save disabled until valid;
  one test per error state; axe clean; full keyboard path.
