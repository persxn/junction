BUILD (apps/desktop only; pin every new dependency exactly and justify each one in the report):
1. Test environment first, because everything below is tested through it: vitest `environment: 'jsdom'`
   for `apps/desktop/**` only (keep node for the backend — use a vitest workspace or an
   `environmentMatchGlobs`-style split), @testing-library/react + @testing-library/user-event +
   @testing-library/jest-dom, and an axe runner (axe-core + a vitest matcher). NO Playwright: §17 wants it,
   WP-16a sets it up. Add the globs to vitest.config.ts and keep one root `pnpm test`.
2. Design tokens (§16.3): Tailwind CSS v4 via @tailwindcss/vite, tokens as CSS custom properties in one
   `src/styles/tokens.css` — neutral surfaces + one accent, semantic tokens (success, warning, danger, info
   and the urgency levels), the 12/13/14/16/20/24/32 type scale, the 4 px spacing grid, radii, focus ring.
   Both themes defined; body text ≥ 4.5:1 in both (assert the computed contrast of the text/background pairs
   in a test rather than trusting the palette).
3. Theme: light / dark / **system**, system honouring `prefers-color-scheme` live (WebView2 follows Windows).
   Preference is per-machine, per-viewer → `localStorage` key `compintel.theme`, every read and write wrapped
   in try/catch and the app rendering correctly when it is empty or throws. `data-theme` on `<html>`.
   Honour `prefers-reduced-motion` (§16.3: 120–200 ms ease-out, drawers/popovers/list changes only).
4. API client — promote `src/shell/backend.ts` into `src/api/`, keeping every guarantee WP-05a/05b proved and
   adding: `Authorization` passed through when a token exists (WP-07a supplies it; design the seam now, do not
   invent auth), problem+json parsed into a typed `ApiProblem` (code, title, detail, hint, retryable,
   requestId, errors[]) using the `ProblemDetails` contract, a `409 CONFLICT` helper for optimistic concurrency
   (§4.4), cursor-pagination types, and R27's 2 s direct-fetch timeout. On a network error: re-read
   `backend_connection()`, and if `generation` changed, retry once with the new secret (§3.2) — otherwise
   surface the error. No SSE client (WP-07a).
5. TanStack Query as the server-state layer (one QueryClient, sensible retry/staleness defaults, an
   invalidation key convention documented in one comment block) and TanStack Router for typed routes, with a
   placeholder page per §16.1 rail item: Dashboard · Discover · Competitions · Teams · Students · Assistant ·
   Notifications. Admin routes exist but are hidden and unreachable until WP-07a can tell us the role — leave
   one clearly marked seam, no fake permissions.
6. App shell (§16.1): collapsible left rail (state in localStorage), top bar with the Ctrl+K search box, a
   freshness-pill placeholder, a notifications-bell placeholder and a user menu carrying theme choice and
   "Exit completely" (the lock and sign-out items arrive with WP-07a). Mica-like surface where it is free;
   never at the cost of contrast.
7. Ctrl+K palette (cmdk): opens on Ctrl+K and on `/` focusing the search box, closes on Esc, lists only what
   exists today — navigate to each route, set theme, open logs, hide to tray, exit completely — and is fully
   keyboard driven with visible focus. No search or NL parsing (WP-15a/25a).
8. States (§16.3): an `ErrorBoundary` that shows what happened, when data was last good and what to do;
   a toast system (one provider, `useToast`, polite ARIA live region, Undo slot for later WPs); `<Skeleton>`
   that only appears after 150 ms; an `<EmptyState>` that always names the next action. One reusable
   `<ConnectionScreen>` replaces the WP-05a diagnostic panel: it renders the R26 cases with their own copy
   (DATA_DIR_LOCKED → "another CompIntel is already using this data folder", DB_CORRUPT → restore from a
   backup), plus Open logs / Copy diagnostics (R25) / Retry. Delete `App.tsx`'s panel and `app.css`.
9. Business logic stays out of components (CLAUDE.md): hooks and modules under `src/api`, `src/shell`,
   `src/theme`; components render what they are given. Files < 400 lines.
