BUILD:

1. **Review (R136, R137).** Do the nine reviews before any adapter code and write them into
   `source-feasibility.md`. Update the §0 summary table and save the robots files. If a "build" candidate fails, it
   becomes a row-only source and the report says so. **Do not look for a way around a refusal** (no other
   endpoints, no browser automation, no signed-in reading; D-28, D-34 applies only to Devfolio and Unstop).
2. **Contracts.** Add `ADAPTER_KINDS` values for the built adapters only (`CODEFORCES_API`, `MLH_PAGE`,
   `HACKEREARTH_PAGE`, `KNOWAFEST_PAGE`), with the contract tests updated. Row-only candidates use the existing kind for
   rows with no adapter (whatever `devpost` uses; read 0012).
3. **Migration 0034 (R141)**: the `sources` rebuild + nine rows. Cadence and politeness per D-27/D-28: 30 min for
   APIs, 60 min for pages, delay = max(3 s, the site's Crawl-delay, its documented rate limit). Codeforces is at least
   2 s per its API rules, so the 3 s floor wins. Request caps are sized from the fixture walk. Prove the rebuild on a
   v0.10.0-shaped database holding scrape runs, records and events from each existing source: row counts unchanged,
   `foreign_key_check` empty.
4. **Adapters (R138, R139)**, one commit each: Codeforces → MLH → HackerEarth → Knowafest. Each maps dates in UTC
   with the site's stated time zone (ADR-0015), mode (online/in-person/hybrid) and location for the geocoder, the
   registration and event URLs, team size and prize text where given. Each also says what is missing rather than
   guessing it. MLH events are all in-person: the geography policy (D-09) keeps the Indian ones and drops the rest,
   and a test proves it. Knowafest keeps technical fests only (R140).
5. **Register** the built adapters in `registerBuiltInAdapters`. Their `scrape:<key>` jobs then appear by themselves
   (WP-09a), and they appear in Connect your sources only if they have a session block, which none of these should.
6. **UI.** Nothing new beyond what the Sources screen already shows. Check that the disabled rows read sensibly there
   ("Manual import only: the Terms forbid automated access", and so on). Update the Discover source filter if it lists
   sources by name. Update README "Features" with the new sources.
7. **Release v0.11.0** the WP-34 way: bump versions, `pnpm --filter @compintel/desktop release`, install on a clean
   data folder, complete a student setup, and record in the handoff how many events each source brought in. Then
   upgrade a v0.10.0 data folder in place and check that nothing it had is lost. Publish on `persxn/junction` with the
   installer, its `.sha256`, and notes that name each new source and each source reviewed and left off.

TESTS (the awkward cases):
- **Per adapter, from captured fixtures:**
  - The golden mapping.
  - An item with no end date, or with only a month: the precision is kept (ADR-0015).
  - An online event with no location; a hybrid one.
  - A changed schema becomes SCHEMA_CHANGED with the body kept (§7.8), never a crash and never a silent empty run.
  - An empty listing is a SUCCESS with zero items, not a failure.
  - A cancelled or removed event takes the §7.6 MISSING path.
- **Codeforces:** only `phase: BEFORE` rounds are new candidates. Gym contests are never requested. A round already
  held from CLIST merges rather than duplicating (R139).
- **MLH:** a non-Indian in-person event is dropped by the policy, not by the adapter.
- **Compliance:**
  - A path outside `allowed_paths_json` is refused before the transport.
  - A disabled MANUAL_IMPORT_ONLY row makes zero requests, and URL import of its domain goes to the manual form (D-30).
  - Robots `Disallow` and `Crawl-delay` are honoured from the saved fixtures.
- **PII:** a fixture-scan test fails if any committed fixture contains an e-mail address or a phone number (D-29).
- **Migration 0034:** the upgrade proof in step 3, plus that each seeded row's verdict matches its review section.
- `pnpm verify` and `pnpm test:a11y` stay green, and **no test opens a socket**.
