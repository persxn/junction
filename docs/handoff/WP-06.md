Deviations from the prompt (why):
- **The top-bar search box is a button, not a text field.** There is no search until WP-15a, and a field
  that accepts text and does nothing is a worse placeholder than a control that opens what does work. `/`
  focuses it and Ctrl+K opens the palette, exactly as asked; it carries `aria-keyshortcuts="Control+K"`.
- **Admin routes are a manifest, not routes.** "Exist but unreachable" cannot both be true of a registered
  route — registering one without a role check makes it reachable by URL. `app/nav.ts` holds `ADMIN_NAV`
  with a commented seam; a test asserts `/admin/users` lands on the not-found page.
- **No `vitest-axe`/`jest-axe`.** The matcher is ~30 lines over `axe-core` in `src/testing/axe.ts`; those
  packages mainly bridge Jest's matcher API and bring their own axe.
- **No date-fns yet.** The only date work here is "when was data last good", which `Intl` covers. §4.2's
  date-fns(-tz) belongs with the first screen that has event dates on it.

Minor decisions made:
1. **Tokens are prefixed `--ci-*`** and mapped onto Tailwind's namespaces with `@theme inline` in
   `app.css`. Tailwind v4 owns `--color-*`/`--text-*`, so an unprefixed token file would collide with it;
   `inline` is what makes `.bg-surface` compile to `var(--ci-color-surface)` and follow `data-theme`.
2. **Contrast is measured, not trusted.** `tokens.contrast.test.ts` reads `tokens.css` off disk and asserts
   WCAG ≥ 4.5:1 for 13 foregrounds × 4 surfaces in both themes (+ the focus ring ≥ 3:1). axe's own
   `color-contrast` rule is disabled in jsdom, where every element computes as transparent.
3. **Urgency levels** are five: critical / high / medium / low / none. §16.3 names "urgency levels" without
   fixing them; these follow §12's deadline radar and are always paired with an icon and a label.
4. **In-memory router history, in the app too.** A desktop window has no address bar and Tauri's asset
   protocol has no SPA fallback, so browser history would only add a way for a reload to land on nothing.
5. **`data-theme` is written before the first render** (`applyStoredTheme()` in `main.tsx`), not in an
   effect, so a dark-theme user never sees a white frame.
6. **The startup-error code is recovered from `lastError` by scanning for it** — `BackendStatus` carries
   prose, not a code. Verified against the real shell: its DATA_DIR_LOCKED message contains the literal
   code. If the wording ever changes the screen degrades to the generic copy plus the verbatim message.
7. **Cursor-pagination types live in `apps/desktop/src/api/pagination.ts`** because this WP is scoped to
   `apps/desktop`; they belong in `packages/contracts` (see the questions).
8. **`apiRequest` supports every method, but the shell proxy refuses non-GET** with a plain "not available
   on this machine" problem rather than a silent failure — widening the proxy needs a ruling (R27).
9. **The generation retry happens once**, then the F9 fallback. A failed `backend_connection()` counts as
   "generation unchanged", so a dead backend still reaches the fallback instead of throwing early.
10. **TanStack Query never retries a 4xx, 409 included** — re-sending a conflict would re-submit a write
    made against a stale `version`. Anything that is not an `ApiProblem` is a bug and is not retried either.
11. **Vitest split into two projects** (`node`, `jsdom`) rather than `environmentMatchGlobs`, which is gone
    in Vitest 5. One root `pnpm test` still runs both.
12. **`"node"` added to `apps/desktop/tsconfig.json` types**, for the one test that reads a file off disk.
    Application code must stay browser-only — a `node:` import in it fails `vite build`.
13. **Mica is approximated on the chrome only** (`.ci-chrome`, a 5 % accent wash on the rail and top bar).
    WebView2 cannot read the real system material, and it never sits under body text.
14. **Toasts with an action stay up 10 s**, plain ones 6 s, so Undo is actually reachable.

2. **Should `BackendStatus` carry `lastErrorCode: StartupErrorCode | null`?** Today the UI recovers it by
   scanning the message (decision 6). One extra field in the Rust shell would make R26 exact instead of
   textual. It is a three-line change in `supervisor.rs` plus the contract.
3. **The search box is a button until WP-15a** (deviation 1). Confirm, or do you want a real input that
   simply opens the palette on the first keystroke?
4. **Admin navigation** (deviation 2): confirm the manifest-only seam, and confirm WP-07a should register
   the admin routes behind a `beforeLoad` role guard rather than only hiding the rail items.
5. **Density.** §16.3 wants "comfortable" by default and "compact" for tables. Tokens exist for the
   spacing, but there is no density switch yet. Does it belong to the first table screen, or to WP-07b's
   settings?
