## 3. Deviations from the prompt

1. **`detail-schema-changed.html` is served as the listing.** The prompt describes it as "buckets
   renamed" and requires "0 events written". Buckets live on the listing page, and a failure on a
   detail page can only happen after listing records are written. The filename is kept as given.
2. **Conditional GET is used on the listing only.** Details are fetched only when the listing hash
   moved. A 304 on a detail would replace the stored detail fields with the listing's thinner ones, so
   details are fetched unconditionally.
3. **The uuid is not validated as 32 hex characters.** WP-02's capture-time redactor rewrote a digit run
   inside one real uuid as `[phone redacted]` (`6434a62d[phone redacted]df8ab42f5a3ef`). The pinned
   fixture is evidence (R62), so the schema accepts any non-empty id of at most 64 characters.
4. **A shared test harness was adjusted.** `main.test`'s startup-handshake cases get 60 s and
   `backend-process.ts` waits 55 s for READY. Under the full suite the first tsx-spawned backend
   reached 22 s. I measured that failure **on the untouched WP-11 commit too**, so it predates this WP.
   While chasing it I found cheerio was adding ~4 s to startup across the file, and made it load
   lazily; startup is back to baseline (40.8 s vs 40.6 s alone).

## 4. Minor decisions

- `paid === false` is a known fee of 0 in **INR** (a zero needs a currency to be "known"), with the text
  "No registration fee (Devfolio)". `paid === true` is unknown, with "Paid — the amount is not stated on
  Devfolio". Absent (the listing) is unknown.
- `aggregatePrizeValue` 0 is "not stated" (feasibility §3.5 saw 0/USD beside a real prize section). A
  positive value becomes the total in minor units; `prizeDetails[]` lines become the text.
- **The organizer is never invented.** It is set only when the venue names a seeded institution, with
  `organizer_kind` at 0.5 confidence; otherwise it is unknown. (The recorded GNIT venue did not match,
  so it stays unknown.)
- A description is tagline + `desc` + a "## FAQ" section; all of it goes through the redactor.
- A robots-skipped detail yields the listing's candidate with `DETAIL_UNAVAILABLE`. In the
  `detail-refresh` path the stored item is a candidate rather than listing JSON, so that case counts
  the item invalid instead.
- `featured_hackathons` is not walked; it repeats the other buckets.
