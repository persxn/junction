## What was built

- **STEP 0:** spec v1.1.23. R112 (baselines: a match set, silent create and re-query, one NEW_MATCH per run) and R113
  (interests are tags; a category interest is an INTEREST tag named by the slug). The numbers were free.
- **Contracts** `saved-searches.ts`: `SavedSearch` (stored query re-parsed with `EventQuery` on read; one that no longer
  parses is `query: null, invalidQuery: true`), create/patch/delete DTOs, `MyInterests`, `MyInterestsView`,
  `MyInterestsUpdate`, tag options. `SAVED_SEARCH_` codes: NOT_FOUND, NAME_TAKEN, VERSION_CONFLICT, QUERY_INVALID.
- **Migration 0031** (`db:generate`): `saved_searches` (§6.2 + `version`, `updated_at`, UQ(user_id, name)) and
  `saved_search_matches` (PK both, cascade from the search and from the event).
- **Domain** `domain/saved-searches/matches.ts` (pure): `diffMatches` against the whole remembered set, `resultHash`
  (SHA-256 of sorted ids), `newMatchNotification`. Its title reads "3 new events match “AI hackathons near campus”"
  and its body lists 3 titles, then "and N more". It is keyed `NEW_MATCH:saved_search:<id>:<hash of the new ids>`.
- **Ids-only path:** `SearchService.matchingIds(userId, query)` runs the same plan, text resolution and `matchedCte`
  as a page of results. Only the projection differs (`SELECT id FROM matched`), so there is no second filter
  implementation. It forces `excludeHidden` and drops sort/cursor/limit.
- **Saved-searches module:** CRUD (owner only; another person's id is 404; `version` → 409; names are unique per
  owner, case-insensitive). Create and query change both baseline silently, in the same transaction.
- **Job `saved-search-evaluator`:** GENERAL, hourly, not network-gated. Each run, per search:
  ids → hash → unchanged? stop → diff → add to the set → one `emit` (honours preferences).
  It is triggered **in-process from the hub** on `source.run.finished` SUCCESS/PARTIAL (R86). Single-flight
  coalesces a burst. A refusal that arrives *after* the running evaluation has read the corpus is remembered and
  answered with one more run, so no run's events wait an hour.
- **Interests module:** view, whole-set PUT (with typed-in names), POST/DELETE one category, tag options
  (TECHNOLOGY · THEME · SKILL, plus earlier INTEREST tags; categories excluded).
  Ranking needs no change: `interestTags` + `interestCategoryIds` already match an `ai-ml` tag to AI/ML.
- **Routes:** `GET/POST /saved-searches`, `PATCH/DELETE /saved-searches/:id`, `GET/PUT /me/interests`,
  `POST/DELETE /me/interests/categories/:id`, `GET /me/interests/tag-options`.
- **Discover:**
  - "Save this search" beside the chips. Its dialog has a name, "Tell me about new matches" (on by default) and the
    filters in words.
  - A **Saved searches** menu beside the tabs: apply (the chips come back, on All events), "Update with current
    filters" (silent re-baseline), rename, alerts on/off, delete with Undo.
  - `/discover/saved/$id` is the route a NEW_MATCH opens. It applies the search, or says it no longer exists.
  - The query comes only from `query.ts` (`savedQueryOf` / `filtersOfSaved`). `presets.ts`'s `filtersToSave` folds
    a tab's defining filter into the chips, so a search saved on Nearby keeps its 100 km.
- **My interests:** reachable from the user menu, from the "Pick your interests to sharpen these" banner on
  Recommended (Discover and the Dashboard panel), and from the drawer's **More like this** on each category chip
  (Undo toast).
  - Categories are checkboxes. Tags use an ARIA 1.2 combobox: ↓/↑/Enter/Esc, "Add “…” as an interest".
  - Any change invalidates every RELEVANCE list key.
  - The dialog carries an in-app guide.
- **Recommended:** every card now prints its two weightiest reasons inline, with all of them under "Why relevant?".
  WP-15b already words both interest codes ("AI/ML matches your interests", "Tagged Rust, one of your interests"), so
  no wording was added.

## UI faults fixed (sweep)

The sweep covered Discover (all tabs, the menu, the dialogs), My interests, More like this, the Dashboard, the Inbox
and the routes they link to.

1. **Inline reasons hid the interest.** WP-15b lists reasons in the order they fire, so "the first two" on a card could
   be "Registration open" (10 points) and the distance, with "AI/ML matches your interests" (20) out of sight. The card
   now shows the two weightiest (`inlineReasons`, ties in server order).
2. **Esc did nothing on an open chip/menu popover while focus was still on its trigger.** That happens right after
   opening with the mouse, or with nothing focusable inside. Esc now closes from the trigger too, and focus returns to
   the trigger when a menu item closes the popover.
3. **A category checkbox ticked one render late** (it waited for the query cache), which also broke Playwright's
   `check()`. The clicked value is held locally and dropped if the write fails. The cache update is optimistic, with
   rollback.
4. **A NEW_MATCH route could not carry the search.** Notification routes are plain paths (`isInternalRoute` refuses a
   query string), so the alert opens `/discover/saved/<id>`, which applies the search. A deleted search says so and
   shows all events.

- Also checked, needing no change:
  - Text scan over Discover, the menu and both dialogs: no enum, slug, ISO string or id.
  - F9: save a search and set an interest with the shell proxy as the only transport.
  - Error states: the menu ("could not be loaded") and the dialog (alert); there is no banner when interests cannot
    be read.
  - Empty menu text and skeletons.
  - The Inbox opens the route.

## Deviations from the prompt

- **The evaluator also runs after a manual entry or URL import commits** (`request()`, the same coalesced trigger).
  Those add events as surely as a scrape does but announce no run. It is also how the e2e's "seeded scrape" is made
  without contacting anything: `seed:demo` switches every source off.
- **The route a NEW_MATCH carries is `/discover/saved/<id>`**, not Discover with a query string (see UI fault 4).
- **`GET /me/interests/tag-options`** was added for the combobox. The existing `/tags` needs `student.view` and offers
  student kinds only. `MyInterestsView` names the options and the tags; `MyInterestsUpdate.newTagNames` carries
  "Add “…” as an interest".
- **`SEARCH_SAVED_NOT_FOUND`**, an unused placeholder, is replaced by `SAVED_SEARCH_NOT_FOUND`. The error-domain test now
  takes a code's domain as the longest registered prefix (`SAVED_SEARCH` has two words). That test moved to
  `errors-domains.test.ts`, which keeps `errors.test.ts` under 400 lines.
- **`main.ts` helpers moved:** `writeReadyLine`, `failStart` and `listeningPort` went to `platform/ready-line.ts` to keep
  `main.ts` under 400 lines.

## Minor decisions made

- Saved searches are personal and **not audited** (like Save/Hide; R113 says so for interests).
- A changed query **clears** the old set before re-baselining: the old query's matches say nothing about the new one.
- A deleted search's Undo re-creates it. What matches then is its new silent baseline.
- `department_id` is the owner's department, else the managing one. It is null only on a database with none.
- Applying a search opens **All events**, the one tab that adds no filter of its own.
- A search saved on a Featured tab folds that tab's filter into its chips (`filtersToSave`); the tab's sort is not saved.
- A picked tag that names a category (an old "AI/ML" tag) counts as that category: the ranking's own rule.
- Interests reach the evaluator only through ranking. They never filter a saved search.

## Demo script (M3 closes here, `seed:demo` data only, D-33)

Run `pnpm seed:demo` and launch CompIntel. Sign in; the app opens on the **Dashboard**.

1. **The Radar.** Open **Deadline Radar**. The seeded competition tasks sit in Today, Next 3 days, Next 7 days and
   Next 30 days, each with an urgency icon and words. A day-only date reads "by 7 Oct" and never "00:00".
2. **Notifications fire once.** Within one five-minute tick the bell shows "1 unread notification" for the item due
   today. Open it to reach its competition; it is marked read.
3. **Snooze.** Back in the **Inbox**, snooze another item for 1 hour. It disappears, and comes back unread on the
   first tick after the hour; it never fires twice.
4. **Interests.** Go to **Discover → Recommended**. A banner says "Pick your interests to sharpen these". Press it and
   tick **Robotics**. The list reorders, and the first card says "Robotics matches your interests" in plain words, with
   "Why relevant?" listing the rest. On any event's drawer, **More like this** beside a category adds it, with Undo.
5. **A saved search and its alert.** Choose **Mode: Online**, type *zebracorn* in the top bar and **Save this search**
   ("Tell me about new matches" is already on). Nothing is announced for what already matches. Add an event titled
   "Zebracorn Robotics Hackathon" (online, with a date) through **Add an event**. Within moments the bell shows one
   "1 new event matches …" item. Open it: Discover comes back with the chips restored and the new event in the list.
