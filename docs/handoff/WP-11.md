## 3. Series detection in one paragraph

Rules run in order. A round platform (codeforces, leetcode, atcoder, codechef, topcoder, hackerrank)
or a known title pattern makes an event a round. Its `seriesKey` is the title without the ordinal,
lower-cased, letters only ("codeforces round div"), and the ordinal becomes `roundLabel`. Cadence
comes from at least 3 siblings in the same family: gaps of about 7, 14 or 30 days give WEEKLY,
BIWEEKLY or MONTHLY; anything else is IRREGULAR. A title carrying a year with no round shape is
YEARLY and **not** a round. Anything else belongs to no series. A hackathon, ideathon, innovation
challenge or CTF is never a round, whatever platform lists it.

Siblings are only visible to the adapter's listing walk, so CLIST computes the series there and
passes it on `candidate.series`. For every other source the linker computes it from the candidate
alone, which still catches yearly editions and titled rounds; CTFtime's "SCAN 2026 Final" now joins
a YEARLY series. The series verdict also sets the `isRecurringRound` claim, so a title-pattern
guess can never contradict the series.

## 5. Deviations from the prompt

1. **Timezone.** "UTC with lowered precision" was not applied to the instants. CLIST states UTC by
   contract (we send no `timezone` parameter), so starts and ends are exact and stay DATETIME. Only
   the event's own zone is left empty, with `TIMEZONE_ASSUMED`. This is the same reading as CTFtime
   in WP-09b, which that handoff also asked about.
2. **`/standings/` is refused as PATH_NOT_ALLOWED, not ROBOTS_DISALLOWED.** The gate checks the path
   allowlist before robots. Either way no request is made, and the test accepts both. `/calendar/` is
   refused the same way.
3. **The CLIST row is enabled.** 0006 said "disabled until U4". The prompt's "missing key → state,
   stays scheduled" requires it to be runnable, and it makes zero requests without a key.
4. **401 is translated in the adapter, not in the classifier.** WP-09a classifies 401 as BLOCKED
   (R60) for every source. Changing that globally would weaken R60, so CLIST's adapter rethrows a 401
   as `HTTP_4XX` with the "key may be invalid" note. It is still not retried.
5. **The settings schema is `z.string()`, not non-empty.** The default is `""` (unset). The route
   enforces non-empty on write.

## 6. Minor decisions

- `kind` is `CLIST_API` (no `API` member exists); `external_key` is `clist:<id>`; the record URL is
  `https://clist.by/contest/<id>/`; `href` becomes both the official and the registration URL.
- `n_problems` becomes a one-line description, "Problems listed by CLIST: N.".
- Mode is ONLINE except on `icpc.global`/`icpc.foundation`, where it is left unstated (UNKNOWN).
- The event type defaults to CODING_CONTEST; a title with "hackathon" is classified HACKATHON by the
  WP-08a rules.
- `organizer_kind` is PLATFORM (0.8), and the organizer name is the resource host.
- A series' recurrence only ever upgrades (IRREGULAR → a concrete cadence), so a later short listing
  cannot erase what a fuller one proved.
- `config_json.auth` names its two settings, and both must be `secret`. Its `missingDetail` is the
  sentence a blocked run records.
- `exportableSettings()` reports a secret as `{ isSet }`. No export feature exists yet (WP-28/30); this
  is the function they must use.

## 7. Bug found and fixed

**Snapshots vanished on Windows for sources whose external key contains a colon.** A new record is
snapshotted under its external key. `clist:910001-….json.gz` names an NTFS *alternate data stream*
on a 0-byte file called `clist`, so the bytes were hidden. `snapshotRef` now maps anything outside
`[A-Za-z0-9._-]` to `_`. There is a regression test in `credentials.test.ts`.

## 8. Known issues / tech debt

- `detail-refresh` builds its request context without a credential. CLIST has no `detail()`, so
  nothing breaks, but a future keyed adapter with a detail step would need it.
- Log redaction is by key name. A secret passed in a field called `value` would not be caught; no
  code does that.
- `auth.recoveryCodeHash` and `backup.privateKeyEncrypted` are not marked `secret`. That's outside
  this WP, but WP-28's export should exclude them too.
