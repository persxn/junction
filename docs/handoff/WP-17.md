# WP-17 — Students, mentorships, CSV/XLSX import

Status: **DONE**, with one acceptance figure unmet (verify wall time; see Known issues).

## Owner decision recorded (replaces the BLOCKED handoff's question 1)

- **XLSX is read by a small in-house reader**: option (a) of the earlier question, chosen by the owner on
  2 Oct 2026 ("carry on with your own recommendations"). `exceljs` is not used: its `uuid <11.1.1` moderate
  advisory has no fixed release, and the prompt forbids an override.
  - The reader is `platform/xlsx/zip.ts` (bounds-checked; entries ≤ 32 MB through `inflateRawSync` `maxOutputLength`)
    plus `sheet.ts` (first sheet; shared and inline strings, numbers, cached formula values).
  - The XLSX twin of `import-500.csv` is written at test time by `testing/xlsx-writer.ts`, not by exceljs.
- **In-app guides on every new screen**, at the owner's request:
  - `components/Guide.tsx` is a collapsible panel (`aria-expanded`); closing it is remembered per viewer in
    localStorage and is a convenience only.
  - Guides sit on the list, the Student page, the add/edit form, the import and Campus & settings.
  - The import guide's **Accepted columns** table is built from `STUDENT_IMPORT_HEADER_ALIASES`. That list
    moved from the backend into the contracts so the guide and the importer can never disagree.

## What was built

- **Contracts:**
  - `students.ts`, `student-import.ts`: limits, fields and labels, actions, preview, commit result.
  - The `STUDENT_*` error codes.
  - `mentorship.manage`, `isSelf` and `canDeactivateStudent` in the permissions matrix.
- **Backend:**
  - Migration 0023: `students`, `student_tags`, `student_achievements`, `mentorships`.
  - `modules/students` holds service, relations, lifecycle (R92 erasure) and import.
  - The import is preview then commit, against a server-held preview (R93): 30 min, 410 on expiry, 404 for
    another user's id, a fresh re-plan at commit and stale rows reported.
  - Two settings, `students.phoneEnabled` and `students.allowExternal`, both off by default.
  - CSV is read by papaparse.
- **Shell:**
  - `picked.rs` handles `pick_file` (native dialog, CSV/XLSX filter, remembers one path) and `read_picked_file`
    (base64; refuses another path, another extension and > 700 KB, naming the limit).
  - `shell/files.ts` wraps both, with an `<input type=file>` fallback that runs the same checks.
- **UI** (`features/students/`):
  - The list: dense table, 50 per page with Load more, search, chips, J/K/Enter.
  - The Student page:
    - Skills carry their level in words; typeahead; optimistic add and remove with Undo; a 409 offers Reload.
    - Mentors, and achievements from before the app.
    - Teams and Competitions shown as empty states that name what will fill them.
  - The form: phone and external fields appear only when their setting is on; a privacy checkbox.
  - Deactivate and reactivate, optimistic with Undo; Erase in a dialog that asks for the roll number.
  - The import wizard: pick → map ("Not imported", never guessed) → preview (counts, "Rows with errors", each
    error under its cell, 200 rows a page) → two checkboxes → result.
  - Admin → Campus & settings is now a real page holding the Students card.
- **`pnpm seed:demo --students --data-dir <set-up dir>`** adds 60 synthetic students (`DEMO0001…`,
  `@example.edu`). Their mentor is a demo professor whose stored hash is a placeholder, so no password verifies.

## UI faults fixed (sweep)

- `Dialog.tsx` updated its `onClose` ref during render (react-hooks/refs). The update moved into an effect, and
  the ref keeps a re-render from stealing focus back to the first field.
- The import preview called `Date.now()` during render. "Kept for N minutes" is now computed once, when the preview
  arrives.
- `aria-selected` sat on a plain table row (an invalid ARIA role/attribute pair). It is now `data-selected`.
- Students bound `/` to its own search, against the shell's global `/`. The binding and its hint were removed.
- A first draft of the import guide said the level syntax was "Python (Advanced)". The importer reads `Python:3`,
  and the guide was corrected after checking `parseTagList`.
- Sweep tests in `students-sweep.test.tsx`:
  - The text scan (enum words, case-sensitive and whole-word, plus ISO timestamps) on the list, the page and the
    import.
  - Forced states: missing student, failed list, skeleton, erased.
  - A 500 on a tag write rolls back with a message.
  - A tag write with the shell proxy as the only transport (F9).
  - The erase dialog's Tab trap, Esc and focus return.
  - The settings switch, and the form without a phone field.

## Deviations

- The Rust code lives in `picked.rs` with its own tests, not in `files.rs`. It is a separate concern
  (user-chosen files, not app files), and putting it in `files.rs` would have taken that file over 400 lines.
- The tag filter is a text box, not chips: tag names are open-ended, and the server matches by name.
- `seed:demo --students` is a separate run on a set-up database. The plain `seed:demo` runs before the setup
  wizard, so there is no organization yet for students to belong to.

## Minor decisions

- `home_department_id` NOT NULL, defaulting to the managing department.
- Interior blank rows are skipped but counted, so row numbers match the spreadsheet.
- An import only adds tags; it never removes them.
- The privacy box is needed only when the import creates students.
- The preview shows 200 rows a page.
