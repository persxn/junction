## What was built

- **STEP 0:** spec v1.1.21 (9 Oct 2026); R106 (one deadline read model) and R107 (disjoint buckets; a KPI is its list's
  own count).
- **Contracts:** `deadlines.ts` (buckets, item kinds, groups, scopes, `DueItem` — WP-23's hand-over — query and
  response with per-bucket counts) and `dashboard.ts` (KPI keys, tile with its `link`, and the shared
  `CLOSING_SOON_REGISTRATION` / `ACTIVE_COMPETITION_STATUSES`, which Discover's preset now reads too).
- **Domain** `domain/deadlines/buckets.ts` (pure, no SQL, injected `now`): `bucketBounds` on Kolkata days via the A7
  helpers, `urgencyOf`, `effectiveDueAt` (DATE = end of that day in the event's zone, MONTH = end of month, UNKNOWN
  left out), `isLive` (a past event deadline leaves; our past work is OVERDUE), `dueItems`.
- **Migration 0029** (custom SQL): the `v_deadlines` view. Drizzle leaves it alone (`db:generate`: no changes).
  **Answer to the prompt's check:** scraped events always get a REGISTRATION `event_deadlines` row, but manually created
  events (and test fixtures) have only the column, and nothing ever writes a submission row — so the view unions both
  columns, each guarded by `NOT EXISTS` a row of that kind; a test proves no id appears twice.
- **Backend:** `modules/deadlines` — one `whereFor` (mine · team · all, group, item kind, events I hid) feeds `rows()`;
  `GET /api/v1/deadlines` buckets at request time and pages by (due, id) keyset; `GET /api/v1/dashboard/kpis` — each tile
  runs its list's own code path (search module for the two Discover tiles, WP-19's list, the Radar). `deadline-evaluator`
  (GENERAL, every 5 min, not network-gated) reads every scope, runs `dueItems`, feeds each `DueItemSink`
  (`registerDueItemSink()` is WP-23's seam; none registered) and logs `{items, byBucket}`.
- **UI:** `/deadlines` — the Radar (groups in bucket order with the server's counts, urgency icon + words, owner links,
  source, honest precision; scope, team, event deadlines vs our work; a link's bucket and kind as removable chips;
  skeleton, empty, error). Dashboard at `/` (replacing the placeholder): KPI strip, Radar top 8, Active teams with
  progress and health reason, Nearby and Recommended (Discover's own cards, reasons, Save/Hide/Assign), a notifications
  card for WP-23; one Mine · Everyone's toggle; each panel loads, fails and empties on its own. One `formatCount`
  shared by the tiles and the Discover, Competitions and Radar headers.
- **Seed:** open competitions' stages and tasks dated into all five buckets; saved events with a deadline in each
  precision.

## Deviations from the prompt

- Buckets are assigned in the domain after the SQL filter (the bucket depends on each event's own zone), and the list
  pages the bucketed set in memory; counts and list therefore share one computation. Fine at a department's scale.
- The two Discover tiles link to the **All events** tab with their chip (dates, registration) so the filter is
  visible as chips, as the AC asks; the Closing-soon filter is the same object the Featured preset uses.
- `GET /deadlines` returns `total` as well as `counts`, so the list header has its own number.

## Minor decisions made

- UNKNOWN-precision dates are left off the Radar (nothing to bucket); MONTH dates fall due at the end of the month.
- "Mine" includes the event deadlines of competitions I mentor, not only saved events.
- An event I hid leaves my event deadlines; work on it stays.
