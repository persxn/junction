## 3. The five decisions worth the architect's eye

1. **The preview reads; the commit writes — and does not read again.** A short-lived per-process
   `PreviewCache` (30 min, 100 entries, keyed by user *and* URL) holds what the preview read, so **one
   import is one request** to somebody else's server and a `source_records` row never carries data a
   request body supplied. A cache miss re-reads an approved source and, for a generic page, saves the
   professor's reviewed entry — which is what they approved anyway.
2. **The record keeps the source's candidate; the overrides carry the professor's.** Both are
   normalized the same way, and `claimValues()` produces both, so "what the page said" and "what the
   professor says" stay two separate statements the resolver can weigh (§7.5) rather than one blended
   row. A box left **blank writes no override**: leaving it empty means "I did not say", not "empty".
3. **`url-import`'s allowance is built per request.** The host a professor pastes is not knowable in
   advance and `allowed_paths_json` cannot say "any host", so the service hands the client an
   allowance of exactly that one host for exactly that one request, with the stored list left empty.
   Nothing else can borrow the row to reach anywhere.
4. **A credential may name its hosts.** `SourceCredential.hosts` is checked in `requestHeaders()`, so
   the session cookie reaching only devfolio.co and its sub-domains is a property of the transport
   rather than a consequence of the path allowlist. The robots fetcher has no source context, so it
   cannot send one even by accident.
5. **A sign-in window is a browser, not a robot.** Its own data directory (never the app WebView's),
   `on_navigation` refusing anything but the source's https hosts, and `cookies_for_url` filtered by
   the same host grammar. Nothing is typed, clicked or solved for the professor.

## 4. Deviations from the prompt

1. **`url-import` is `is_enabled = 1`**, not 0. That flag is what the compliance gate reads on the one
   user-initiated request, and it is the switch an administrator turns URL import off with. It can
   still never be scheduled: jobs come from the intersection of the adapter registry and the enabled
   rows, and `URL_IMPORT` is never registered (WP-09a). `manual` is disabled, as asked — it makes no
   request ever. (`manual` also carries `max_requests_per_run = 1` only because the column's CHECK
   demands ≥ 1; its `allowed_paths_json` is empty.)
2. **The routes live in `src/routes/events.ts`**, not inside `modules/events/import/`. §3.3 and every
   other route in the repo put the HTTP layer there; the module holds the service the route calls.
3. **Onboarding's "Connect your sources" step is not built.** The sign-in flow lives in Admin →
   Sources, which is where it is reopened from anyway. Adding a step to WP-07b's wizard is a change to
   the first-run contract (R39/R40) and reads better after WP-30 gives that screen its source table —
   **say if you want it in this WP instead.**
4. **Admin → Sources is a sessions panel, not §16.2's full table.** Run history, freshness and "Run
   now" are WP-30's; the screen says so rather than showing an empty table.
5. **"Two source records for one event"** is proved as *a manual entry and an import of the same URL
   merging* (`joins a typed-in event to the page it was imported from`). Importing the same URL twice
   updates one record — the external key is the same — and the test asserts one event either way.
6. **`sessionState` and `sessionVerifiedAt` are not `secret`.** The cookie and its capture time are;
   the state is what Source status shows an administrator, and "expired" has to be legible in a
   diagnostics dump for the screen to be worth anything.

## 5. Minor decisions

- The registrable parent is approximated from the last two labels plus a short public-suffix list
  (`ac.in`, `co.uk`, …). A full PSL is a dependency and a monthly update for a decision whose worst
  case is that a campus URL takes the generic path it was taking anyway.
- `www.` is stripped and only https is accepted, so one page is one URL for §7.5's matching.
- The generic path passes the `url-import` row's `defaultTimeZone` (Asia/Kolkata) as the source zone.
  Without it every prose date on a campus page is read as UTC and has its precision lowered for it,
  which throws away the day printed on the page.
- A label's value ends where the next label — or a call to action ("Register now") — begins. A campus
  page is a table of labels, not sentences, and there is no full stop to stop at.
- D-29 applies to the **preview** as well: `importFields()` redacts what it shows, because what the
  professor sees is what the commit sends back.
- A manual event with no link is recorded under `https://manual.compintel.invalid/<key>` (RFC 2606,
  never resolves); a link the professor gave is used instead when there is one.
- Ten previews a minute per user. §7.1 calls URL import user-initiated, and that is the ceiling that
  keeps a stuck screen from becoming a crawler.
- `manual` has `trust_rank` 90 and `url-import` 70 — above the registration platforms, below a typed
  entry. Overrides beat everything regardless; the rank only settles fields nobody overrode.

## 7. Known issues / tech debt

- The preview cache is per process: a backend restart between preview and commit costs one extra
  request to an approved source. Nothing is lost, and nothing is stale-read.
- `SessionCard` has an "Open sign-in window" and a separate "Use this session" button; the window
  cannot tell the UI it is done, because no event flows back from it yet. A `WindowEvent` listener
  would make it one button.
- The generic extractor reads one `<time datetime>` pair positionally (first = start, second = end).
  Good enough for the fixtures; a page that lists a deadline first will need the professor's eye.
- Devfolio's provisional external key (`devfolio:slug:<slug>`) exists only between `itemFromUrl` and
  `normalize`; the record is always written under the candidate's own key. It would be cleaner if
  `ListingItem` could say "key unknown yet".
- `routes.test.ts`'s 1 MB body-limit test still times out under the full suite about one run in three
  (seen since WP-09b); it passes alone every time.

## 8. Questions for the architect

1. **Deviation 3:** should the onboarding "Connect your sources" step land in this WP, or with WP-30's
   source screen?
2. **Deviation 1:** is `url-import` being `is_enabled = 1` the reading you want, given that the
   registry is what actually keeps it unscheduled?
3. Should a **manual event with no link** get a real URL of some kind, or is the reserved
   `.invalid` URL acceptable in the provenance drawer (WP-16b will render it)?
4. The commit trusts the client for *which* fields were edited. A body claiming everything was edited
   would pin values the professor never touched — their own values, so no data is lost, but the event
   stops tracking its source. Worth tightening by diffing against the cached preview?
