## UI faults fixed (step 8 sweep)

1. **Focus fell out of the assign dialog** when a step changed: the Next button that had focus is replaced on the last
   step, so focus went to the page behind the dialog and Tab walked the page. Each step's heading now takes focus.
   Found by the keyboard-only walk.
2. **Focus fell out of the board after a move:** the moved card is a new element in another column. Focus now follows
   it there.
3. **Discover's "Assign" was a disabled placeholder** (WP-16a). It is now live on the card, the A key and the drawer.
4. **The students e2e assumed it ran alone** ("3 students."). It now finds its own students by name, so the specs can
   share one backend in any order.
5. The text scan now covers statuses, kinds, removal reasons, warning codes, mentor roles and the word "engagement".
   Clean on the board, the list with closed competitions, and a closed competition's page. Forced states checked:
   unknown competition, no competitions, failing list, slow board. A status change with the shell proxy as the only
   transport (R78/F9) passes.

## Minor decisions

- Error codes beyond the prompt's list: `ENGAGEMENT_VERSION_CONFLICT`, `ENGAGEMENT_MENTOR_NOT_FOUND`,
  `ENGAGEMENT_PARTICIPANT_NOT_FOUND` (WP-18 has the same three for teams).
- A drop on a disallowed column still asks the server, which refuses with its `detail`. The card returns and shows
  that sentence, so the UI never words a refusal differently from the API.
- The board ignores the status filter (it shows every open column); the list honours it. Closed competitions appear
  only with "Show closed".
- Assigning students individually: an admin naming another primary reuses `team.transfer_ownership` (admin only),
  as WP-18's team creation does.
- `discoverSearch` now parses whatever the previous screen's search was, since Competitions also has a `view`.
